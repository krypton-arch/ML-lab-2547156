1.4 — Feature scaling using StandardScaler¶

Why scaling matters for KNN: KNN classifies a point based on the (typically Euclidean) distance to its nearest neighbours. If features are left on their raw scales, a feature like mean area (values in the hundreds to low-thousands) will completely dominate the distance calculation over a feature like mean smoothness (values around 0.05–0.15), even if the smaller-scale feature is just as informative for distinguishing malignant from benign tumours. StandardScaler transforms every feature to have mean 0 and standard deviation 1, so all 30 features contribute proportionally to the distance metric instead of the result being dominated by whichever feature happens to have the largest raw magnitude.

Task 3: KNN Model with Heuristic K Selection¶

3.1 — Heuristic method for K selection¶

A commonly used heuristic for an initial guess at K is:

$$K \approx \sqrt{n}$$

where n is the number of training samples. The square-root rule is a rough rule-of-thumb (not a theoretically optimal value) that tends to avoid K values that are either too small (noisy, overfit) or too large (oversmoothed) for typical dataset sizes. We also round to the nearest odd number to avoid tie-votes in the binary classification.

In [10]:
X_train, X_test, y_train, y_test = split_data["80:20"]
n_train = len(X_train)

k_heuristic_raw = np.sqrt(n_train)
k_heuristic = int(round(k_heuristic_raw))
if k_heuristic % 2 == 0:      # force odd K to avoid tie votes in binary classification
    k_heuristic += 1

print(f"Number of training samples (n)     : {n_train}")

print(f"Heuristic K (rounded, forced odd)   : {k_heuristic}")

3.3 — Distance metrics, and decision boundary mapping¶

Euclidean Distance¶

$$d(p, q) = \sqrt{\sum_{i=1}^{n} (p_i - q_i)^2}$$ This is the ordinary straight-line ("as the crow flies") distance between two points in feature space. It is the default and most common metric for KNN and works well when features are continuous, on comparable (scaled) ranges, and the geometric notion of "closeness" is meaningful — exactly the situation here after StandardScaler.

Manhattan Distance¶

$$d(p, q) = \sum_{i=1}^{n} |p_i - q_i|$$ Also called "city-block" distance, because it sums the absolute differences along each axis, as if you could only travel along a grid (like city blocks) rather than diagonally. Manhattan distance is less sensitive to outliers in individual features (differences aren't squared, so one very large deviation doesn't dominate the sum) and tends to be preferred in high-dimensional spaces or when features represent counts/grid-like structure. For this dataset (30 continuous, scaled, roughly-Gaussian features) Euclidean distance is the more natural and commonly used choice, but Manhattan is worth comparing when features are noisy or contain outliers.

Decision boundary mapping¶

The dataset has 30 features, which cannot be visualised directly. To visualise how the decision boundary changes with K, we project the scaled data down to its first two principal components (via PCA) purely for plotting purposes, and train a 2-D KNN on that projection for K = 1, 5, 10, and 20.

Observation — how the boundary changes with K:

  • K = 1: the boundary is highly jagged / irregular, hugging individual training points closely. This is the classic signature of overfitting / low bias, high variance — the model memorises noise and outliers in the training data.
  • K = 5: the boundary is noticeably smoother, averaging over a small local neighbourhood; it still adapts to the true curve of the class boundary without chasing every single point.
  • K = 10: smoother still — the boundary is close to a single broad, gently curved separating region.
  • K = 20: the boundary becomes the smoothest and simplest, approaching a nearly linear/very gently curved split. Very large K starts to underfit — it averages over such a wide neighbourhood that fine local structure in the true class boundary is lost (high bias, low variance).

This progression is the direct visual illustration of the bias–variance trade-off controlled by K (see Task 7, Q5).

Task 4: Cross Validation¶

A single train-test split gives only one estimate of accuracy, which depends on which rows happened to land in the test set. K-Fold Cross-Validation instead splits the (training) data into k folds, trains on k−1 folds and validates on the remaining fold, rotating through all folds — giving k accuracy estimates whose mean is a far more reliable measure of how the model will generalise. We apply this with cv = 5 and cv = 10, across a range of K values, on the full (scaled) dataset.

In [15]:

cv_results = {"K": k_candidates, "CV=5 Mean Accuracy": [], "CV=10 Mean Accuracy": []}

for k in k_candidates:

Regression vs Classification evaluation — conceptual differences¶

Error-based evaluation (Regression): the target is a continuous number (GPA, salary). Metrics like MAE, MSE, RMSE, and R² all measure how far a numeric prediction is from the true value — they quantify a magnitude of error on the same (or a squared) scale as the target. A prediction can be "a little wrong" or "very wrong," and these metrics capture that gradation directly.

Decision-based evaluation (Classification): the target is a discrete label (Malignant/Benign). A prediction is either correct or incorrect — there is no "partially correct" class label (though the predicted probability can be more or less confident). Metrics like Accuracy, Precision, Recall, F1, and the Confusion Matrix count correct vs incorrect decisions, broken down by which type of decision error was made (false positive vs false negative), rather than measuring a numeric distance.

Direct metric comparisons¶

R² Score vs Accuracy — R² measures what fraction of the variance in a continuous target is explained by the model (can range from very negative to 1); Accuracy measures what fraction of discrete predictions exactly match the true label. Both are single summary numbers between (effectively) 0 and 1 that describe "overall goodness of fit," but R² is about explained variability of a numeric quantity, while Accuracy is about the count of correct classifications — and, critically, Accuracy can be misleading on imbalanced classes in a way R² has no direct analogue for.

RMSE vs F1 Score — RMSE punishes large numeric errors more heavily (because errors are squared before averaging, then square-rooted back to the original units), giving a sense of typical prediction error magnitude. F1 Score is the harmonic mean of Precision and Recall — it balances two competing types of classification error (false positives vs false negatives) into one number. Both are "single-number summaries that penalise being badly wrong," but RMSE penalises numeric distance while F1 penalises an imbalance between the two decision-error types.

MAE vs Confusion Matrix — MAE gives one average absolute error across all predictions — a single number. The Confusion Matrix, in contrast, gives a full breakdown of every combination of true label vs predicted label (TN, FP, FN, TP) — much richer than a single number, because in classification which mistake was made (false positive vs false negative) usually matters as much as how many mistakes were made, whereas in regression an error of "+5" and an error of "−5" (before squaring/abs) are usually treated symmetrically.

Continuous prediction tasks vs classification tasks¶

Continuous (regression) tasks ask "how close is the number?" — evaluation is about distance/magnitude on a continuous scale, and a model can be graded on a smooth spectrum from "great" to "terrible." Classification tasks ask "was the decision correct, and which kind of mistake was it?" — evaluation is about counting discrete outcomes and, especially in domains like medicine, weighing different mistake types very differently (a missed cancer diagnosis is not equivalent to a false alarm, even though both are simply "one wrong prediction").

Inference¶

  • Regression metrics (MAE, MSE, RMSE) measure the magnitude of numeric prediction error — how far off, on average, a predicted GPA or salary is from the actual value, in the same (or squared) units as the target; R² additionally expresses this as the proportion of variance explained, giving a scale-free sense of overall fit quality.
  • Classification metrics (Accuracy, Precision, Recall, F1) measure decision correctness — not how "far" a prediction was, but whether the discrete label was right, and if wrong, which type of error (false positive vs false negative) occurred.
  • Accuracy is insufficient in medical diagnosis because the classes are imbalanced (more benign than malignant cases here) and, more importantly, because the two error types have wildly different real-world costs: a false negative (calling a malignant tumour "benign") can delay life-saving treatment, while a false positive (calling a benign tumour "malignant") leads to further tests but not a missed cancer. A model that simply predicts "benign" for everyone could still score a deceptively high accuracy while catching zero actual cancers.
  • Recall and ROC-AUC are more relevant in healthcare because Recall (specifically for the malignant/positive-for-disease class) directly answers "of all the actual cancer cases, how many did we correctly catch?" — the question clinicians actually care about — while ROC-AUC summarises how well the model separates the two classes across every possible decision threshold, which is valuable when the "right" threshold for calling a case malignant may be tuned differently depending on clinical risk tolerance (e.g. screening vs confirmatory testing).
  • Overall comparison: regression evaluation is fundamentally about measuring distance on a continuous scale, while classification evaluation is about measuring and categorising discrete decision correctness — and in high-stakes classification domains like healthcare, a single summary number (whether Accuracy or R²-style) is rarely enough; a full breakdown of error types (Confusion Matrix, Recall by class, ROC-AUC) is essential to a defensible evaluation.

Task 7: Analytical Questions¶

1. Why is KNN called a lazy learning algorithm? KNN does not build an explicit generalised model during a "training phase" — it simply stores (memorises) the entire training dataset. All of the actual computation (finding the K nearest neighbours and voting) is deferred until prediction time, when a new query point actually needs to be classified. Because no learning/generalisation work is done up front, it is called a lazy (instance-based) learner, as opposed to eager learners like Linear Regression or Decision Trees, which build an explicit model (coefficients, splits) during training.

2. Why is feature scaling required in KNN? KNN relies on distance calculations (typically Euclidean) between points across all features simultaneously. If features are on very different scales (e.g. mean area in the hundreds vs mean smoothness around 0.1), the large-scale feature will dominate the distance computation regardless of how informative each feature actually is, distorting which points are considered "nearest." Scaling (e.g. StandardScaler) puts every feature on a comparable scale so each contributes fairly to the distance metric.

3. Explain heuristic K selection using the √n rule. The rule sets an initial candidate value $K \approx \sqrt{n}$, where n is the number of training samples. It is a simple, commonly cited rule of thumb (not derived from a formal optimality proof) that scales K sensibly with dataset size — larger datasets get a larger starting K, which tends to avoid a K so small it overfits to noise, while not being so large that it oversmooths the boundary. It is meant as a reasonable starting point for further tuning (e.g. via a K-sweep or cross-validation), not a guaranteed optimum.

4. Why is cross-validation more reliable than a single train-test split? A single train-test split gives one accuracy number that depends heavily on which rows happened to fall into the test set — a "lucky" or "unlucky" split can over- or under-state true performance. K-Fold Cross-Validation repeats the train/evaluate cycle across multiple different partitions of the data and averages the results, which reduces the influence of any one particular split and gives a more statistically stable estimate of how the model is likely to perform on unseen data.

5. How does K affect the bias-variance trade-off?

  • Small K (e.g. K = 1): the model follows the training data very closely, producing a highly flexible, jagged decision boundary → low bias, high variance (overfitting; sensitive to noise and outliers).
  • Large K: the model averages over a wide neighbourhood, producing a smooth, simple decision boundary → high bias, low variance (underfitting; may miss real local structure in the class boundary). The goal of tuning K (heuristically and via cross-validation, as done in Tasks 3–4) is to find the point that balances these two competing sources of error and minimises overall generalisation error.

6. Why is recall more important than accuracy in cancer prediction? In cancer prediction, a false negative (a malignant tumour incorrectly classified as benign) is a missed diagnosis — the patient does not get needed treatment, which can be life-threatening. Accuracy treats all correct/incorrect predictions equally and can stay high even while missing many actual cancer cases, especially when classes are imbalanced. Recall (for the malignant class) specifically measures "of all the true cancer cases, how many did the model correctly catch?" — directly targeting the error type (false negatives) that matters most clinically, which accuracy does not isolate.

7. What is the limitation of very large K values? As K grows very large (approaching the size of the whole training set), the model's predictions become increasingly dominated by the overall class distribution rather than by any local structure near the query point — in the extreme, a KNN with K = n simply predicts the majority class for every single query, regardless of its actual features. This causes underfitting: the model loses the ability to capture genuine, locally-varying decision boundaries, and on imbalanced datasets it can bias predictions heavily toward the majority class.

Conclusion¶

  • Optimal K: the √n heuristic gave an initial estimate that was then refined using a local K ± 5 sweep on the train-test split and confirmed against 5-fold and 10-fold cross-validation; the cross-validated result was adopted as the final K, since CV gives a more statistically reliable estimate than a single split.
  • Effect of train-test split variations: the 80:20, 70:30, and 90:10 splits produced very similar accuracy for this dataset, but smaller test sets (90:10) give noisier, less stable accuracy estimates, while larger test sets (70:30) trade away some training data for a more statistically reliable evaluation — a direct illustration of the evaluation-side bias–variance trade-off discussed in Task 2.
  • Model performance: the final KNN model achieved high accuracy, precision, recall, F1, and ROC-AUC on the held-out test set, with the confusion matrix confirming very few misclassifications in either direction.
  • Key differences between regression and classification evaluation: regression metrics (MAE, MSE, RMSE, R²) quantify the magnitude of numeric error, while classification metrics (Accuracy, Precision, Recall, F1, ROC-AUC) quantify decision correctness and error type; the latter is essential (over a single summary number) in domains like medical diagnosis where false negatives and false positives carry very different real-world consequences.
  • Insights from Lab 3 vs Lab 4: Lab 3's regression models (GPA and Salary prediction) were evaluated purely on how close numeric predictions were to the truth, whereas Lab 4's KNN classifier required a richer toolkit of metrics precisely because "correct vs incorrect" alone (Accuracy) does not capture which kind of mistake a model makes — a distinction that matters most exactly in high-stakes classification settings like cancer detection.
